# Публикация в Render

Проект разворачивается как два связанных сервиса из одного GitHub-репозитория:

- `weather-consensus-web` — статический React-интерфейс;
- `weather-consensus-api` — FastAPI с live-прогнозами Open-Meteo.

Оба сервиса описаны в корневом файле `render.yaml`. Адрес API автоматически
передаётся интерфейсу при сборке, а адрес интерфейса — backend для настройки
CORS. Секреты для текущего live-режима не требуются.

## Первый запуск

1. Отправьте актуальную ветку проекта в GitHub.
2. Откройте [Render Blueprints](https://dashboard.render.com/blueprints).
3. Нажмите **New Blueprint Instance** и подключите GitHub, если он ещё не
   подключён.
4. Выберите репозиторий проекта. Render найдёт `render.yaml` автоматически.
5. Подтвердите создание двух сервисов и дождитесь статуса **Live**.
6. Откройте адрес сервиса `weather-consensus-web`.

После этого новые изменения в основной ветке автоматически запускают сборку и
публикацию обоих сервисов.

## Что важно знать о бесплатном запуске

API использует SQLite только как восстанавливаемый кэш прогнозов. В бесплатной
конфигурации файловая система сервиса временная: после перезапуска кэш может быть
утрачен и будет заново наполнен данными Open-Meteo.

Для постоянного хранения следует перейти на платный сервис с persistent disk и
смонтировать его в `/workspace/apps/api/data`. Если в продукте появятся
пользовательские или другие невосстанавливаемые данные, вместо SQLite следует
подключить управляемый PostgreSQL.

Бесплатный API может засыпать после периода без обращений. Поэтому первое
открытие приложения после простоя иногда занимает дольше обычного.

## Настройки production

`render.yaml` автоматически задаёт:

- `DATA_MODE=live`;
- `VITE_API_BASE_URL` — публичный адрес API;
- `CORS_ORIGINS` — публичный адрес интерфейса;
- небольшие последовательные пакеты Open-Meteo, чтобы не превышать ограничения
  бесплатного API;
- `/api/health` — проверку работоспособности API.

Локальный запуск через Docker Compose и `.env` продолжает работать как раньше.
