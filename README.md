# Amur Weather Consensus

MVP агрегатора прогнозов ECMWF IFS, NOAA GFS и DWD ICON для контрольных точек
Амурской области. Интерфейс сравнивает независимые модели, показывает среднее,
медиану, модельные экстремумы, разброс и понятный Model agreement. Это не сплошная
карта региона и не официальный сервис метеорологических организаций.

## Быстрый запуск

Требуются Docker и Docker Compose:

```bash
cp .env.example .env
docker compose up --build
```

- интерфейс: http://localhost:3000
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs

По умолчанию работает полностью автономный `DATA_MODE=mock`. Для реальных данных
установите `DATA_MODE=live` и перезапустите контейнеры. API-ключ Open‑Meteo для
некоммерческого использования не нужен; проверьте актуальные
[условия](https://open-meteo.com/en/terms).

## Интерфейс

Главная страница поддерживает три фиксированных горизонта: «Сегодня», «3 дня» и
«7 дней». Горизонт и выбранная дата сохраняются в URL. Для многодневных режимов
доступны дневные карточки, выбор конкретного дня и обзор всего периода с отдельными
графиками температуры, осадков и ветра. В дневном режиме показываются карта,
таблица, экстремумы и подробные почасовые графики точки. Прошедшие часы текущего
дня визуально приглушены.

## Структура и поток данных

- `apps/api/app/providers` — три model-specific адаптера.
- `apps/api/app/statistics` — чистое статистическое ядро.
- `apps/api/app/services` — mock/live orchestration и presentation DTO.
- `apps/api/app/db` — SQLite TTL-кэш исходных и нормализованных данных.
- `apps/web/src` — React, TanStack Query, React Leaflet и Recharts.
- `data/amur_points.json` — 20 контрольных точек.

Endpoints: `GET /api/health`, `GET /api/points`, `GET /api/forecast`,
`GET /api/forecast/{point_id}`, `GET /api/summary`, `POST /api/refresh`.

Endpoints прогноза принимают `horizon=today|3d|7d` (`today` по умолчанию) и
опциональный `date=YYYY-MM-DD`. Период всегда начинается с текущей календарной
даты по `Asia/Yakutsk`: `today` содержит один день, `3d` — сегодня и следующие
два дня, `7d` — сегодня и следующие шесть. Дата вне горизонта возвращает HTTP 422.

## Модели и расчёты

Конфигурация явно использует:

- `https://api.open-meteo.com/v1/ecmwf?models=ecmwf_ifs025`
- `https://api.open-meteo.com/v1/gfs?models=gfs_global`
- `https://api.open-meteo.com/v1/dwd-icon?models=icon_global`

Best Match и seamless не используются. Координаты отправляются пакетами, запросы
асинхронны, ограничены тремя соединениями, имеют timeout и максимум три попытки
только для временных ошибок.

Числовой консенсус содержит count, arithmetic mean, median, min/max с источниками,
range и population standard deviation. При двух моделях он помечается неполным,
при одной не рассчитывается. Направление ветра использует круговое среднее; медиана
для него намеренно отсутствует. Суточные осадки сначала суммируются по часам
отдельно для каждой модели, затем сравниваются между моделями.

Дневные показатели также сначала вычисляются внутри каждой модели: минимум,
максимум и средняя температура; сумма осадков; средние влажность, давление,
облачность и скорость ветра; максимальная скорость и порыв; круговое направление.
Только готовые дневные результаты ECMWF, GFS и ICON поступают в консенсус.
Периодные агрегаты строятся из тех же модельных дневных рядов и содержат тёплый,
холодный, дождливый, ветреный и наиболее расходящийся день, а также абсолютные
экстремумы с датой, временем, точкой и моделью.

Open‑Meteo приводит данные моделей к почасовому временному ряду. В частности,
ICON Global после 78 часов интерполируется из 3-часового шага, а ECMWF IFS после
90 часов переходит с нативного часового шага на более редкий и также приводится API
к часу. Собственная интерполяция приложением не выполняется.

Model agreement — описание разброса, а не вероятность точности. Для температуры и
скорости ветра: до 2 — высокое, свыше 2 до 5 — среднее, свыше 5 — низкое.
Пороги остальных показателей централизованы в `config/models.py`.

## Кэш, ошибки и допущения

При загрузке backend всегда запрашивает и сохраняет единый семидневный набор.
Переключение `today`/`3d`/`7d` только фильтрует этот набор и не обращается к
Open‑Meteo повторно. TTL задаётся `FORECAST_CACHE_TTL_SECONDS` (3 часа по
умолчанию), а `POST /api/refresh` обновляет все семь дней и защищён process-local
lock. Если одна live-модель недоступна, API
возвращает две и предупреждение; ложный консенсус из одной модели не строится.
Логи структурированы и содержат request ID, полные ответы на INFO не выводятся.

MVP использует один процесс API и SQLite. Lock не является распределённым.
`model_run` остаётся `null`, поскольку стандартный JSON-ответ этих endpoints не
гарантирует время запуска модели. Региональная сводка относится только к выборке.
