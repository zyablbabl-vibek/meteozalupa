# Архитектура

Один общий pipeline обслуживает все регионы:

```text
Region registry
→ ForecastPoint
→ model-specific Open-Meteo adapters
→ UTC/local normalization
→ region-scoped SQLite cache
→ statistics
→ insights
→ FastAPI
→ React UI
```

`app/regions` загружает registry и отдельные наборы точек, вычисляет metadata и
валидирует id, координаты, IANA timezone, административный центр и GeoJSON.
Бизнес-логика прогноза не дублируется по регионам.

Каждая нормализованная запись содержит `region_id`, `point_id`,
`point_timezone`, `forecast_time_utc`, `forecast_time_local` и `local_date`.
Локальная дата вычисляется по timezone точки. Диапазон интерфейса определяется по
`primary_timezone` выбранного региона; это не меняет календарную агрегацию точек.

SQLite содержит справочники `regions`, `forecast_points`, исходные ответы и
нормализованный кэш. Составные индексы разделяют данные по региону, дате, точке,
модели и времени загрузки. Миграция старого кэша добавляет `region_id`
неразрушающим `ALTER TABLE`; старые JSON-записи без нового контракта игнорируются
и обновляются лениво.

Live-режим запускает три независимых адаптера. Координаты разбиваются на chunks,
а общий лимит соединений задаёт максимальный параллелизм. Ошибка одной модели не
ломает регион; статистика сохраняет partial status. Модели не смешиваются до
статистического слоя.

React сначала загружает `/api/regions`, затем прогноз выбранного региона.
TanStack Query включает region id в ключи. `RegionMap` пересоздаётся при смене
региона, поэтому старые маркеры не сохраняются; center и zoom берутся из registry.
GeoJSON считается необязательным опубликованным ресурсом: отсутствие файла
никогда не блокирует точки и базовую карту.

Полное состояние навигации (`region`, `horizon`, `date`, `section`, `view`,
`point`) сериализовано в URL и восстанавливается через `popstate`.
